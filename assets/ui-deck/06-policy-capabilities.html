Reversibility-aware gating

Global rules that shape when prompts fire — independent of per-tool defaults above.
Auto-allow reversible, git-backed edits
File changes that land inside a git worktree are auto-approved and logged — they're reversible with one command. No prompt needed.
Always gate irreversible / destructive commands
Commands that delete, overwrite, or mutate state outside git's reach are always held for human review — regardless of per-tool defaults.
locked
Require type-to-confirm for high blast-radius actions
High-blast actions show a confirmation prompt requiring you to type the action name. Prevents muscle-memory approval of consequential steps.

Blast-radius classes

Three tiers — each maps to an approval burden proportional to consequence.
Low
Reversible & scoped
Action is git-backed or isolated to target/. Full rollback in one command. No external state mutated.
Auto-allowed + logged
Med
External or persistent
Affects remote state (git push, network call) or persists beyond the run. Rollback requires coordinated effort.
1 named approver
High
Irreversible or broad
Deletes outside git, drops DB rows, or affects unbounded scope. Loss cannot be recovered automatically. Self-approval forbidden.
Named role + type-to-confirm

Per-action prompts fire only for capability-escalating or irreversible steps that were not in the approved plan. Eliminates prompt chains for routine multi-step work.
